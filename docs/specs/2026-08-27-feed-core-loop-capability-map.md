# Atoman Feed 首访到首读能力地图

## 状态

Implementation in progress，视觉/交互 brief 已确认。本文只定义本阶段边界。

## 目标

把 Atoman 的公开内容发现和登录后的 Feed 使用串成一条可完成的路径：

`发现文章或来源` → `打开详情` → `需要登录时安全回跳` → `订阅来源` → `继续阅读` → `收藏或稍后阅读`

本阶段的用户不是内容创作者，而是第一次访问 Atoman、希望建立可靠内容订阅流的读者。

## 能力地图

| 模块 ID | 责任 | 依赖 |
| --- | --- | --- |
| `discovery-entry` | 公开首页与 Feed 发现页展示真实内容，支持打开文章和来源详情 | 无 |
| `auth-return` | 访客触发需要账号的操作时进入登录，并保留原始页面、筛选和来源意图 | `discovery-entry` |
| `subscription-commit` | 登录后完成来源订阅，刷新订阅数据，并明确反馈下一步 | `auth-return` |
| `reading-state` | 第一次阅读后可收藏、加入稍后阅读、区分未读状态 | `subscription-commit` |

构建顺序：`discovery-entry` → `auth-return` → `subscription-commit` → `reading-state`

## 第一条垂直切片

本次只实现一条最短可验证路径，不重做 Feed 信息架构：

1. 访客进入 `/feed`，看到文章和推荐来源。
2. 访客可以打开来源抽屉和来源文章列表。
3. 访客点击订阅时进入 `/login`，`redirect` 只允许站内相对路径。
4. 登录成功后返回原始 Feed 筛选状态，并重新打开待订阅来源；不自动执行有副作用的订阅。
5. 用户明确点击“订阅”后，来源状态变为“已订阅”，订阅列表同步刷新，来源文章仍可继续打开。
6. 文章详情中的收藏和稍后阅读继续使用现有 Feed store 能力。

- `src/router/guards.ts`：受保护路由的 `redirect` 生成。
- `src/views/auth/LoginView.vue`：安全回跳与默认登录目标。
- `src/views/feed/FeedRecommendedView.vue`：文章、来源、筛选、来源抽屉和搜索。
- `src/components/feed/FeedSourceIdentityCard.vue`：来源卡片及订阅操作。
- `src/components/feed/FeedSourceArticlesSheet.vue`：来源文章列表及订阅操作。
- `src/stores/feed`：订阅、收藏和稍后阅读状态。

## 交互与视觉 brief

### 视觉方向

保持现有 Atoman 的克制、内容优先和纸面式 UI。第一屏优先展示真实文章与来源，不新增营销 Hero、装饰性渐变或新的卡片层级。推荐页仍以双流结构为主，但订阅按钮必须对访客可见，并清楚表达“登录后订阅”。

### 关键状态

- 加载：沿用文章流和来源流 skeleton，避免只显示居中 spinner。
- 空内容：说明当前筛选没有结果，并提供切换分类或主题的动作。
- 请求失败：说明内容未能加载，并提供明确的“重试”。
- 未登录：文章和来源仍可读；订阅、收藏和稍后阅读触发登录，不静默失败。
- 订阅处理中：按钮禁用并显示处理中，避免重复请求。
- 订阅成功：来源立即显示已订阅，使用 `aria-live="polite"` 的简短成功反馈；用户可以留在来源抽屉继续阅读。
- 订阅失败：保留来源和文章上下文，明确提示失败原因或重试动作。
- 移动端：来源抽屉、登录回跳和订阅按钮在窄屏下不溢出，所有主要触控目标至少 44px。

### 焦点顺序

页面标题 → 搜索 → 语言和筛选 → 文章列表 → 来源列表 → 来源抽屉标题 → 订阅按钮 → 来源搜索与文章列表。登录返回后焦点应落到来源抽屉标题或订阅按钮附近，不应回到页面顶部。

## 边界

### 始终执行

- 复用现有 API、Pinia、Vue Router 和 UI primitive。
- 先补失败测试，再写行为代码。
- 保留查询参数和站内 redirect 的安全校验。
- 验证桌面和移动端的加载、空、错误、未登录、成功状态。

### 需要先确认

- 是否把无 redirect 的普通登录默认目标从 `/` 调整为 `/feed`。
- 登录回跳后是否只恢复待订阅来源，还是同时恢复用户输入的搜索下拉状态。
- 是否在本阶段新增埋点；若新增，先确定事件名和数据归属。

### 本阶段不做

- 新增推荐算法、个性化召回或后端数据表。
- 新增顶层内容模块。
- 重做 Portal 首页视觉。
- 重新设计 Feed 订阅管理、OPML、分组规则。
- 改动收藏、稍后阅读和未读的后端语义。

## 验收标准

- 访客可在不登录的情况下浏览推荐文章和来源文章。
- 访客点击来源订阅会进入登录，且不会丢失 Feed 的查询上下文。
- 登录成功后不会发生开放重定向，也不会自动重复提交订阅请求。
- 登录后能回到待订阅来源，明确点击后完成订阅。
- 订阅成功、重复订阅、网络失败和来源消失均有可理解的 UI 状态。
- 文章详情、收藏和稍后阅读不因本次登录回跳改动而回归。
- `bun run type-check`、相关 Vitest 测试和 Feed/Auth 核心 E2E 通过。

1. 认证用户访问 `/` 时优先跳转到 `/feed`，匿名用户继续看到公开 Portal。
2. 访客订阅通过 `/feed?...&subscribe_source_id=<id>` 保留筛选和来源意图。
3. 登录回跳后只恢复来源抽屉，用户需要再次明确点击订阅。
4. 订阅成功反馈为“已订阅，可继续阅读”，不额外增加重复的去阅读按钮。
