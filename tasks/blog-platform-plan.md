# 博客平台完整能力计划

## 目标

在不重复建设现有能力的前提下，把博客从“可以发布和阅读”补齐为“可发现、可订阅、可治理、可持续优化”的闭环。

现有后端计划 [blog-development-plan.md](/root/Atoman/Atoman-Backend/docs/superpowers/plans/blog-development-plan.md) 是统一模型、版本、定时发布、Markdown、搜索、标签、推荐、治理和 RSS 的基础规格。本计划只负责剩余实现、前端接入和验收，不改变其中已经确认的产品边界。

## 已有能力，不重复开发

- 版本、恢复、归档和定时发布基础。
- Markdown 导入、受控导出和媒体资源校验。
- 文章阅读、评论、评分、收藏、稍后阅读和订阅时间线。
- 结构化搜索、推荐、SEO 元数据和作者/频道/合集 RSS 的基础 API。
- Studio 基础数据分析接口和博客编辑器基础流程。

## 能力地图

| 模块 | 责任 | 依赖 |
| --- | --- | --- |
| `blog-runtime-gate` | 路由、弹层、发布和关键流程稳定性 | — |
| `blog-discovery` | 搜索、标签、作者/频道/合集发现 | `blog-runtime-gate` |
| `blog-retention` | 个性化开关、画像清除、阅读行为闭环 | `blog-discovery` |
| `blog-governance` | 举报、自动隐藏、申诉和审核 | `blog-runtime-gate` |
| `blog-distribution` | RSS、分享、SEO 和公开入口验收 | `blog-runtime-gate` |
| `blog-author-console` | 编辑器、发布状态、分析和批量管理的前端闭环 | `blog-runtime-gate` |

## 实施顺序

### 阶段 0：运行时和契约门禁

1. 建立文章、频道、合集、发布、阅读和 RSS 的桌面/移动端冒烟测试。
2. 修复并锁定列表点击、弹层渲染、返回、刷新、深链和发布后跳转。
3. 对 API 错误、加载中、空状态和权限拒绝统一验收。

完成标准：文章和频道从首页、博文页、作者页、频道页都能打开；发布后的公开 URL 可刷新恢复；无权内容不出现在列表、搜索、推荐和 RSS。

### 阶段 1：发现闭环

1. 完成标题、摘要、作者、频道、合集、标签的 AND 搜索和稳定分页。
2. 接入作者标签和公共用户标签：添加、撤回、作者/管理员移除、频率限制和计数排序。
3. 增加作者、频道、合集的互相跳转和相关文章入口。
4. 完善移动端搜索、筛选、标签展示和空/错误状态。

完成标准：读者能从搜索或标签进入文章；搜索结果严格遵守可见性；分页、筛选和返回状态可恢复。

### 阶段 2：留存和推荐控制

1. 统一打开、有效阅读、完成阅读、订阅、收藏、稍后阅读等行为事件。
2. 增加账号级“个性化推荐”开关和“清除推荐数据”操作。
3. 关闭个性化后回退到时间顺序；新用户使用新鲜度与热度冷启动。
4. 增加最近 90 天行为清理和账号删除清理。

完成标准：开关跨设备同步，清除后画像重置，不扩大任何文章可见范围。

### 阶段 3：内容治理

1. 统一文章、评论和公共标签举报模型与固定理由。
2. 实现重复举报限制、7 天/3 人阈值自动隐藏、待复核状态。
3. 实现作者一次申诉、管理员恢复/归档、结果反馈和审计记录。
4. 接入文章详情、评论、标签和管理端界面。

完成标准：举报者身份不泄露；自动隐藏和恢复是事务性的；作者和管理员权限边界有测试。

### 阶段 4：作者工作台补齐

1. 将版本、定时任务、导入导出、发布失败重试状态集中到文章管理页。
2. 补齐博客分析视图：阅读、打开、有效阅读、评论、收藏、分享、来源、回访和文章排行。
3. 增加批量筛选、批量移动合集和定时任务列表。
4. 完成桌面/移动端编辑器的恢复、错误提示和离开保护。

完成标准：作者可以从一个工作台完成文章生命周期管理，并能解释每篇文章的表现。

### 阶段 5：公开分发和质量验收

1. 验收作者、频道、合集 RSS 的完整正文、稳定 GUID、绝对媒体 URL、归档移除、缓存和限流。
2. 验收文章的 canonical、Open Graph、Twitter Card、JSON-LD、分享链接和 sitemap。
3. 增加关键流程 Playwright 桌面/移动验证和无障碍键盘验证。
4. 运行前后端构建、受影响单测、API 契约测试和发布门禁。

完成标准：公开文章可被搜索引擎和 RSS 客户端稳定消费；所有关键流程可回归验证。

## 明确不做

- 邮件 newsletter 和站内通知扩建。
- 团队协作编辑、协作者邀请和发布前统一审核队列。
- 标签独立聚合页、标签关注和跨模块统一标签。
- 语义搜索、正文全文搜索和复杂搜索语法。
- 逐字版本 diff、版本评论和复杂运营后台。

## 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 统一模型迁移仍有残余 legacy 引用 | 高 | 阶段 0 先做代码搜索、API 契约和数据一致性门禁 |
| 推荐事件记录无权内容 | 高 | 候选过滤先于排序，统一复用可见性函数 |
| 举报阈值误伤正常内容 | 高 | 固定理由、人工复核、申诉和完整审计 |
| 桌面与移动路由行为不一致 | 中 | 每阶段都跑双端关键流程，而不是只测组件 |
| 现有全量测试存在无关失败 | 中 | 阶段报告区分基线失败和本阶段回归，不降低本阶段门禁 |

## 总完成定义

- 所有阶段验收标准通过。
- Backend `go build ./...` 和相关测试通过。
- Frontend `bun run type-check`、受影响单测和生产构建通过。
- 桌面/移动关键流程验证通过。
- API 文档、迁移说明、失败清单和回滚/前向修复步骤齐全。
