# Atoman 长期开发计划

- 状态：生效
- 范围：Atoman-Backend、Atoman-Frontend、Atoman-Mirror 及移动端
- 周期：2026-12 至 2027-11，每月复盘
- 最后更新：2026-11-23（替换 2026-08-20 草案）

## 1. 定位与已确认决策

Atoman 是一个**以求真为核心的社区**：读到可靠信息，围绕事实、证据和逻辑表达与讨论。主线是“读 → 想 → 辩”：

- **Feed** 提供每天回来的理由；
- **短话、论坛、辩论** 承载表达与交锋；
- **时间线、书摘、引用** 提供证据。

| 决策 | 结论 |
| --- | --- |
| 产品定位 | 求真社区，而非个人信息工作台 |
| 模块合并 | 不合并；各模块保持独立入口，按分级控制投入 |
| 产品遥测 | 不采集产品事件；仅保留已上线、不含个人数据的客户端错误上报，用于可靠性 |
| 人力 | 一人开发；同一时间只推进一条主线 |

## 3. 模块分级（不合并，只控制投入）

| 级别 | 模块 | 投入规则 |
| --- | --- | --- |
| 核心 | Feed、博客/短话、论坛、辩论、时间线 | 主线功能只在这里开发 |
| 维护 | 音乐、图书、邮件、Studio、私信、通知 | 只修缺陷、安全和兼容问题，不接新功能 |
| 冻结 | 播客、视频、推荐 | 保持可用，只修严重缺陷 |

分级每季度复盘一次；调整需写入第 10 节决策登记。

## 4. 一人开发的工作方式

1. **同一时间一条主线。** 每周约 80% 投入当前阶段，20% 用于维护级缺陷与运维。
2. **小切片可发布。** 每个切片 1–2 周，独立 worktree、独立提交、可回滚。
3. **双周发版。** 每两周打 tag 并写发布说明；禁止“前端先上、后端未部署”。
4. **先闭环再扩张。** 加载、空状态、错误、重试、移动端、权限和测试齐全才算完成。
5. **复用而非新建。** 引用、举报、审核、通知走共享能力，不按模块各写一套。

## 5. 度量（不采集遥测）

只用服务端已有数据做**按月聚合统计**，不记录个人行为轨迹：

- 新注册账号数、月内有发布/回复行为的账号数；
- 新增帖子、回复、短话、辩论论点数，以及带引用的比例；
- 新增订阅数与订阅源健康率；
- 生产错误：API 错误率、客户端错误按版本与路由聚合（已有，无个人数据）。

定性来源：站内反馈帖、私信与邮件反馈。每月复盘时记录在发布说明中。

## 7. 阶段 1：读 → 议（2027-01 至 2027-04）

**目标：** 让阅读自然地变成有证据的讨论。

1. **引用卡片（共享能力）：** 统一的引用对象，可引用 Feed 文章、博客、书摘、时间线事件和站内帖子；展示来源、时间和原文片段。
2. **从阅读发起讨论：** Feed 文章与书摘可一键发起短话、论坛帖或辩论，并自动附引用卡片。
3. **结构化辩论：** 论点 / 证据 / 反驳三层；证据必须挂引用；辩论投票与结论区分“支持度”与“证据充分度”。
4. **时间线作为证据库：** 补齐时间线事件的创建、来源标注与被引用回链，保持独立入口。
5. **讨论回访：** 关注的帖子与辩论有新进展时站内通知，并提供每周站内汇总页（不做邮件推送统计）。

**验收：** 每月新增讨论中带引用的比例可统计并逐月上升；辩论详情能展示论点—证据—反驳结构；引用失效（源删除）有明确展示。

## 8. 阶段 2：治理与信誉（2027-05 至 2027-07）

**目标：** 在扩大公开参与前，让社区可以被一个人管住。

1. 统一举报入口与审核队列，覆盖论坛、辩论、短话、博客评论、图书。
2. 声誉权重：基于被引用、被采纳的证据和违规记录，影响发言频率限制与审核优先级；规则公开。
3. 社区规范与处置记录公开页面；处置可申诉。
4. 一人运营工具：批量处置、关键词与新号限流、审核待办看板。

**验收：** 所有可公开发布的内容都有举报与处置路径；单日审核可在 30 分钟内完成。

## 9. 阶段 3：智能阅读与来源扩展（2027-08 至 2027-11）

1. 单篇摘要与长文要点；每周订阅摘要。频率、范围和生成内容保留时长由用户控制，摘要必须附原文引用。
2. Newsletter 来源：复用站内邮件为用户提供订阅收件地址，投递内容进入 Feed。
3. YouTube / 视频来源接入 Feed，在来源归属、删除与署名策略确定后进行。
4. 研究性准备（不承诺交付）：公共 API 的 scope、限流与审计设计；浏览器扩展；移动端阅读连续性。

**验收：** 摘要可关闭、可删除、附引用；新来源停用时不损坏用户资料库。

## 11. 每月复盘

- 对照当前阶段验收标准，记录完成、进行中、风险。
- 查看第 5 节聚合数据与反馈，删除没有可见结果的工作。
- 只有当前切片可发布时，才调整下月优先级。
- 结果写入当月发布说明，并同步 `ROADMAP.md`。

## 12. 执行顺序

1. 发布止血
2. 读 → 议
3. 治理与信誉
4. 智能阅读与来源扩展

可以提前研究后续阶段，但不得挤占当前阶段的验收。
